# ADR-0001 — Tauri 2 as the desktop shell

**Status:** Accepted · 2026-08-19

## Context

Mira must run on macOS, Windows, and Linux from one codebase; reach deep into the OS
(processes, sockets, D-Bus, WinRT, distributed notifications); start in well under a
second; idle under 150 MB; and ship an installer small enough that a free tool is a
painless download. It is also a tray-resident app that is open for seconds at a time,
which makes idle cost more important than peak performance.

## Decision

Build on **Tauri 2**, using the OS webview for UI and a Rust host process for everything
else.

## Alternatives considered

**Electron.** The most capable and best-documented option, with the deepest ecosystem.
Rejected on arithmetic: a bundled Chromium is ~150 MB installed and 100–200 MB resident
before the app does anything, against budgets of 30 MB and 150 MB. For a tray tool that
sits idle all day, that cost is paid permanently for a benefit Mira does not need. Node
would also make the system layer JavaScript, which pushes us toward native modules for
exactly the work that matters most.

**Wails (Go).** Same webview approach, lighter than Electron, good ergonomics. Rejected
because Go's story for macOS system APIs and WinRT is cgo-heavy, and the Rust ecosystem
has better-maintained crates for every one of our services (sysinfo, zbus, windows-rs,
objc2, git2). We would be writing more FFI, not less.

**Native per platform** (SwiftUI + WinUI + GTK). The best possible result per OS, and
three codebases for a project with no team. Rejected as unshippable at this size; it also
guarantees feature drift between platforms, which is precisely what the parity rules
forbid.

**Flutter.** One codebase, excellent rendering, weakest of the options for deep system
access and tray/menu-bar integration on desktop; system work would land in platform
channels anyway, so we would pay for a runtime and still write the native layer.

**Tauri 1.** Superseded; v2 brings the reworked capability/permission system that
[ADR-0006](0006-no-account-no-cloud.md) and the security model depend on.

## Consequences

**Good.** Installer ~10–20 MB, idle RSS well inside budget. Rust is a first-class part of
the app rather than an escape hatch — which suits a product that is mostly system
inspection. The capability system lets us give the frontend *no* ambient privileges. The
official plugin set covers global shortcut, tray, single-instance, autostart, updater,
and window state.

**Bad.** Webview differences are now our problem: WKWebView on macOS, WebView2 on Windows,
WebKitGTK on Linux, each with its own CSS and API quirks — and WebKitGTK is the weakest
and most variable across distros. We must test on all three. WebView2 must be present on
Windows (bootstrapper handles it; some locked-down machines still need attention). The
ecosystem is younger than Electron's, so some problems have no Stack Overflow answer.
Rust raises the contribution bar for backend work.

**Accepted risk.** WebKitGTK quirks will cost real debugging time on Linux. Mitigated by
keeping the UI plain (no exotic CSS, no WebGL) and by CI on all three platforms from
Slice 1.
